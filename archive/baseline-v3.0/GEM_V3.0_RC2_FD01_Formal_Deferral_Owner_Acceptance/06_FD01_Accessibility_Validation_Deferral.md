# 06 · FD01 — Accessibility Validation Deferral (FD-G03, SR-12)

**GEM™ V3.0 RC2 — OWNER ACCEPTED WITH FORMAL DEFERRALS · SYNCHRONIZED · OWNER ACCEPTED AS-IS · FORMAL DEFERRALS RECORDED · NOT YET FINAL-RELEASE AUTHORIZED**

## Decision
Windows-native assistive-technology validation (SR-12: NVDA / JAWS, Windows Word and Word Online) is **FORMALLY DEFERRED BY BRAND OWNER**. It was not performed. Reason: it is outside the currently available environment and has been postponed by Brand Owner decision. This replaces the earlier HR01 deferral, which had been recorded on the content owner's authority and noted as not an Accessibility QA authorization; the Brand Owner's formal deferral is now the recorded authority.

## Scope statement
| Scope | Status |
|---|---|
| macOS VoiceOver (HR01: SR-01–SR-10, SR-13; 13 sampled reading-order slides) | **COMPLETED / PASS FOR DEFINED SCOPE** — REVIEWER OBSERVED (Mashal). Preserved unchanged |

| Windows Word / Word Online | Not tested (also listed in the D8 rule) |

## What this does not say
- It does not say cross-platform accessibility is verified.
- It does not say WCAG 2.2 AA is certified, conformant or fully demonstrated. VAL-08 also still has unmeasured text-over-picture contrast, no formal exceptions and no independent Accessibility QA holder.
- It does not invalidate or weaken the macOS evidence, and it does not turn the deferral into a pass.

## Register position
- VAL-08's criterion reads "WCAG 2.2 AA target tested in real digital/document outputs; issues resolved or formally excepted". A formal exception is a recognised route, but FD01 creates no exception record for specific findings and does not close VAL-08.
- VAL-07 (screen-reader order passing native review) keeps its Windows-side evidence formally deferred; its other conditions are unchanged.

## Reopening trigger
A Windows environment becomes available, or the AC20 decision requires the evidence.
